# Living Site Demo v9

## 目标

让 Little Works 在一个约 210 秒的循环中展示完整施工过程，而不是所有对象同时重复动作。

## 施工周期

| 进度 | 阶段 | 主要活动 |
| --- | --- | --- |
| 0–18% | 基坑与测量 | 挖机、渣土车、测量员、监理巡检 |
| 18–38% | 基础与钢筋 | 钢筋绑扎、材料搬运、混凝土车进场 |
| 38–78% | 主体结构 | 楼柱、梁板逐层生长，塔吊吊运钢筋与料斗 |
| 78–92% | 安装与收尾 | 高层作业、清理道路、监理逐层验收 |
| 92–97% | 完工展示 | 建筑完整显示，机械归位，照明巡检 |
| 97–100% | 新工期转场 | 扬尘增强并平滑回收模型，随后进入下一循环 |

## 人员角色

- 普工：黄色安全帽，承担绑钢筋、工具作业、搬运、清理和安全通道巡逻。
- 监理：白色安全帽，携带记录板，执行测量、楼层检查和塔吊指挥。
- 高层工人只有在对应楼板完成后才出现，不允许悬空。

## 时间系统

- 黎明：暖粉橙天空、低角度暖光、较长阴影。
- 正午：高亮蓝灰天空、白色主光、最高环境照度。
- 黄昏：深橙紫天空、低角度侧光、工地灯开始点亮。
- 夜晚：深蓝天空、冷色环境光、探照灯与板房窗户主导。

## 验收

- 四个固定时刻的画面颜色和照度可通过像素与灯光指标区分。
- 建筑进度从基础到三层完整结构单调增长，并在循环末端重置。
- 28 名工人均有角色、任务和有效出现阶段。
- 挖机、渣土车、搅拌车、塔吊、装载机只在对应阶段作业。
- 车辆净距违规为 0，桌面 GPU 采样目标不低于 45FPS。

## 实现结果

- 楼体使用 396 个动态实例，其中 138 个为永久结构；永久结构完成度在六个
  手动采样点从 0 单调增长至 1。
- 人员编制为 23 名黄帽普工和 5 名白帽监理。监理拆分为巡检与塔吊指挥，
  普工承担钢筋、工具、搬运和通道巡检任务。
- 巡检与搬运采用带端点停靠的往返节拍：出发、到位检查或卸料、返回、取料。
  人物只在行进方向变化时转向，不进行连续原地旋转。
- 挖机负责基坑，渣土车负责早期外运和后期清场，搅拌车负责基础与主体浇筑，
  两台塔吊负责钢筋与混凝土吊运，装载机负责前期整平和后期清障。
- 97% 后进入扬尘转场，人员与活动设备先退场，楼体随后回收；新周期开始后再进场。

## 实测结果

| 检查 | 结果 |
| --- | --- |
| 四时光照 | 天空色、太阳强度、环境光、灯光系数和曝光均不同 |
| 工序矩阵 | 0.08、0.30、0.48、0.65、0.84、0.96 六点通过 |
| 角色 | 23 名普工、5 名监理；黄帽/白帽指标与画面一致 |
| 循环 | 207.9 秒转场时人员与活动设备均为 0，随后回到基坑阶段 |
| 碰撞 | 六个工序采样点和转场采样均为 0 次违规 |
| 离线 | 单 HTML 在 `file://`、断网模式下无外部请求 |
| Canvas | 桌面 520 种中心采样色，手机 809 种，均为非空画面 |
| 性能 | 桌面 59–60FPS，手机 59FPS；实际值仍取决于硬件 |
| 全站 E2E | 35 通过、3 个按设计跳过、0 失败 |
