## 设计决定

这仍是一座可以随意观察的桌面微型工地，不是工程设计工具。保留正在工作的基坑、楼架和机械，用外围空间补齐真实工地的配套关系。

- 场地由 27.5 × 20.25 扩至 31.5 × 24.25 模型单位，面积增加约 37.2%。这些数值不是实际工程尺寸。
- 后侧材料场：模板、木方、原料架、工作台、成品垫木和分类料箱。
- 后侧生活／安全驿站：休息与急救、卫生间、饮水消防，房门朝通道。
- 前侧入口：门岗、轮洗格栅、沉淀回收设施；齐平入口铺装接回原环路。原车队仍沿内部环路行驶，不声称已模拟进出场或冲洗流程。
- 单独的人行入口接绿色步行带，沿外围连向后场。运输路线、装载机路径和 28 名人员的活动原位保留。
- 围挡、底板和工作台同步扩建，旋钮、蓝图、卷尺和安全帽外移。

场地色板：钢蓝 `#496d80`、混凝土灰 `#a8aca4`、安全黄 `#e6b747`、通道绿 `#66887f`、作业橙 `#d47e45`、碎石米 `#b5a080`。沿用手札原有文字层级及等宽数据字体，不下载新字体或纹理。

视觉重点是从入口到后场的空间关系，刻意避免用更多车辆、灯光和粒子表现“热闹”。用高低细节模型保留不同设施的轮廓，近处再看到构造。

## 性能约束

三区合计预算：近景 ≤435 个方块，远景 ≤41 个方块。最终为 **260 / 41**（入口 52/9，材料 133/18，生活 75/14）。全部共用现有 BoxGeometry 和粗糙材质，各区远近批次互斥。未新增活动人员、车辆、真实灯光、天气粒子或外部资源。

道路、办公室窗户、灯头分别合批；相同尺寸轮胎／轮毂、旋钮和光晕复用几何。暂停时，未变化的工人矩阵和雨滴缓存不重复上传；雨滴使用固定 typed buffer，并仅上传当前画质实际使用的范围。六处静态屋顶碰撞在初始化时预计算。轻量模式保留帧时间余量，避免显示刷新抖动导致重复错过目标帧。

仪表改用未截断的真实帧间隔计算 FPS／平均／P95。Three.js r160 的默认统计会排除阴影；本轮改为在整帧开始前清零，显示的绘制与三角形数量包含阴影。帧间隔并非 GPU 或纯渲染耗时。

### 实际浏览器对照

同一台机器、同一个内置浏览器；施工固定 65%，关闭自动绕行与昼夜流转。表中“精细”均固定相同阴影与 **1.0× 像素比**，未用自动降分辨率掩盖成本。绘制与三角形包含主场景及阴影。通过公开设置面板读取稳定采样窗口（每窗至少 1.5 秒）；这不是纯 GPU 耗时测试，也不代表所有设备。

| 条件 | FPS 前 → 后 | 绘制 前 → 后 | 三角形 前 → 后 | P95 帧间隔 前 → 后 |
| --- | --- | --- | --- | --- |
| 1280×800 精细，全景正午 | 60 → 60 | 202 → 190 | 60,114 → 62,364 | 18.7 → 18.6 ms |
| 1280×800 精细，全景雨夜 | 60 → 60 | 203 → 191 | 60,114 → 62,364 | 18.7 → 18.6 ms |
| 1280×800 轻量，全景雨夜 | 26 → 30 | 136 → 133 | 30,882 → 32,256 | 50.1 → 35.4 ms |
| 1280×800 精细，原西侧后勤近景 | 60 → 60 | 176 → 170 | 60,518 → 67,202 | 18.6 → 18.6 ms |

全景首次晴天几何资源由 80 降为 38；雨滴首次显示后各增加一个至 81 / 39。纹理由 18 增至 21，新增三张程序生成标牌。全景三角形增加约 3.7%，原西侧近景因为同时看见新材料与入口细节而增加约 11%；在本机对照中未见帧率下降，绘制批次有余量，但不能据此保证低端真机没有 GPU 压力。自动／轻量适配仍保留。

桌面已目视检查全景、材料区、生活驿站、门岗与雨夜；观察手札包含 11 个分区、新镜头及总图入口。标牌固定到门岗／檐棚或补立柱，新增回水槽；接缝、步行带、蓝图与围挡开口的末轮审查均已处理。

390×844 竖屏检查中发现原固定垂直视场会裁掉扩大后的场地。现在竖屏使用 42° 水平视场、较高全景角度及相称的雾强度，保持原画质档位、阴影与像素比；桌面镜头不变。已截图确认完整台面及生活区近景，手机上选择分区后自动收起手札并提示当前位置。该响应式尺寸测试仍在同一台电脑运行，不等于手机硬件实测。
