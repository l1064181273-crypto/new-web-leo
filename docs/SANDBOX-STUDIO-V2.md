# Little Works · Studio V2

> 2026-09-13 更新：已在保留 V2 备份的基础上扩建场地、入口、材料周转场与生活安全驿站。最新布局、性能对照与验收见 [SANDBOX-EXPANSION-V3.md](./SANDBOX-EXPANSION-V3.md)。下文是此前版本的历史记录。

## 设计意图

一张可以慢慢观察的模型工作台。观众是愿意点开微型世界的朋友；单一任务是让人看懂、操控并发现这座工地，而不是展示求职指标。

延续原版几何建筑、黄铜机械、深灰地台与真实工序。大胆的部分集中在“工地手札”：像一张贴在模型旁的观察记录，内容跟随施工和选中的分区变化，读完可以直接走近相应位置。

- 颜色：工作台墨灰 `#202A31`、工具钢蓝 `#516C7C`、薄雾白 `#E7EEEE`、安全黄铜 `#D9B86D`、测量青绿 `#86B3B2`、信号橘 `#DD986B`。
- 字体：标题采用系统窄体/人文无衬线的克制粗细；正文使用系统中文无衬线；工序编号、时间与实测状态使用系统等宽。
- 布局：三维场景占满窗口；顶部是简洁身份与动作；左侧可收起手札；下方为暂停、施工进度、速度和观察设置；手机手札改为可关闭的底部抽屉。
- 取舍：不增设与工地无关的指标卡，不把所有设置常驻在场景上；高级设置收进可用键盘操作的对话框。

```text
Little Works                         手札  留影  全屏
正午 · 晴朗                               比例 1:48
┌ 工地手札 ┐
│工序/分区/图鉴│           三维微型工地
│故事/观察入口 │
└ 可收起 ──┘
      暂停  ───施工时间轴───  速度  观察设置
```

## 已实现

- **工序手札**：六章对应基坑、基础、一层、上层、围护、验收。叙述来自模型内真实动作；文字随施工进度切换。可选工序静看，也可从当前进度接回自动施工。
- **自定步速导览**：六站各自选择工序、镜头和时刻；可前后切换、退出，结束后保留末站场景。导览没有倒计时，不会把人强行带离正在看的细节。
- **八个分区**：基坑、主体、加工棚、办公室、运输环路、西侧后勤、管线带、东侧预制。分区页与可选场地标牌都能走近相应位置，并切到适合观察的工序。
- **机械与人员图鉴**：2 台挖掘机、2 座塔吊、2 辆自卸车、1 辆搅拌车、1 台装载机、28 名现场人员。每页有实际动作说明和“看看它工作”入口。
- **世界控制**：施工进度、一天中的分钟、昼夜流转、时间流速、雨天、扬尘、自动环绕。空格暂停会同时冻结施工、机械、雨和昼夜；镜头仍可观察。
- **镜头**：保留原有全景、街道、工人、塔吊，加入真实分区及俯视预设。提供键盘方向旋转、0 归位、+ / − 缩放、触屏拖动与双指缩放。
- **焦点避让**：手札展开时采用投影偏移，把观察目标放在右侧可见区域中心，OrbitControls 仍围绕真实目标旋转。基坑改从西北上方观察，避开加工棚和前景道路；装载机有专属镜头。手机选区会收起手札露出目标，照片导出则自动回正构图。
- **留影**：导出本地 PNG，画面下方有当前工序、进度、时刻和天气。窄屏照片用两行字幕，防止文字相撞。支持浏览器允许时的全屏观察。
- **观察存档**：显式“保存此刻 / 恢复观察”，保存光线、天气、工序、机械时钟、车队时钟和准确镜头。恢复后先暂停。损坏存档、存储被禁用或已满均有真实状态说明；不上传到服务器。
- **性能与可靠性**：自动 / 精细 / 轻量三档画质，轻量降低雨尘数量、关闭阴影并限制 30 帧。自动档按屏幕和实际帧率降低像素密度；手动或暂停时不重复上传未变化的建筑实例矩阵。父桌面隐藏或页面后台时不推进世界，也不绘制。
- **小窗口独立适配**：正文 12px、观察说明 11px；430–550px 高窗口采用常驻工序快捷行、紧凑页眉、可点击滚动提示与更近的全景。手机手札默认收起，打开为底部抽屉；所有高级选项仍可在设置中操作。
- **加载与恢复**：桌面 iframe 用真实 ready/error 握手决定载入状态，慢加载提供重试；上下文丢失显示恢复入口。离线版仍由构建脚本把所有 HTML、CSS、Three.js 和场景内容内联为一个文件。

## 可靠性复审（2026-09-12 18:42）

本轮仅修复控制与导出边界，不改变几何、交通路线、镜头预设或视觉布局。

通过先写针对性回归测试，实际复现并修复了以下问题：

1. **分钟显示偏移**：原先的双重取模与向下取整，使 1440 个可选分钟中 459 个显示为前一分钟，存档归一化也会影响滑块回显。现在保留有效日内小数，并在统一的分钟换算中吸收浮点尾差；逐分钟检查当前显示和保存后的显示。

3. **PNG 异步下载异常没有反馈**：原外层 `try/catch` 不能捕获 `toBlob` 回调内的失败。现在分别处理编码为空、画布不可用、对象 URL/下载触发失败，并恢复按钮；WebGL 丢失时不导出空白照片。下载链接临时挂入文档后触发，随后移除；对象 URL 延迟 60 秒释放，给异步下载处理留出时间。

## 错误边界复审（2026-09-13）

本轮限定为 WebGL 启动/恢复、绘制失败、全屏拒绝与保存失败；没有调整交通、几何、镜头预设、粒子数量、分辨率或画质目标。

先添加四个失败回归，原实现均实际失败，然后作最小修复：

1. **GPU 绘制抛错**：原 RAF 在每一帧开始先安排下一帧，直接调用 `renderer.render`；若 GPU 绘制边界抛错，会持续重试和重复抛错。现在捕获此边界，显示“重新载入”操作，标记绘制失败并暂停后续 GPU 绘制；保存的观察不受影响，也不会继续导出空白照片。
2. **恢复过早宣称成功**：原 `webglcontextrestored` 立即隐藏错误并向桌面报告 ready，没有验证重建后的渲染器能够绘制。现在初始化和自动恢复都只在一次真实 `renderer.render` 成功后报告 ready；恢复后仍不能绘制时继续显示错误。恢复时重置帧率采样，保持既有的用户暂停状态。
3. **恢复后焦点进入隐藏区域**：用户聚焦错误区的“重新载入”按钮期间，WebGL 可能自动恢复。现在成功恢复时把焦点交还画布；如果错误内容更新，会保留在新重试按钮上，不把聚焦节点直接移除。
4. **全屏退出拒绝提示相反**：进入和退出全屏的 Promise 拒绝原先共用“没有开启全屏”提示。现在退出失败明确提示“暂时无法退出全屏，可以按 Esc 退出”，按钮仍保持真实全屏状态；进入失败保留原来的独立打开建议。

未发现需额外修改的路径：

- WebGL 构造失败和渲染器初始化失败，本来就有中文错误、可工作的重新载入按钮及正确的父页面 error 握手。新增两个独立启动 guard 测试，执行真实入口代码，分别注入构造/初始化失败，不创建实际 GPU。
- 本地保存的 quota/权限拒绝已有处理。本轮增强原测试：预先保存一份有效观察，再拒绝下一次写入；旧记录逐字节保留且恢复按钮仍可恢复它，没有另造一套重复覆盖。
- reset 取消路径依赖原生 `<dialog>` 的正常焦点返回。当前 jsdom stub 只模拟 open/close，不模拟浏览器焦点算法，不能由此宣称真实故障或添加假修复；等待主 agent 真实浏览器验收。
