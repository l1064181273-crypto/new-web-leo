## 沙盘规则没有被整体替换

以下原验证仍保留：Three r160、实例和绘制调用存在、地台面积扩展、车辆与灯柱 / 边界净距、零违规、28 名工人及角色 / 安全帽分布、前后摆腿与无侧摆、围栏岗位分布、办公室不侵入、静止车辆轮胎不转、工人运动、六段施工活动、永久建筑单调完成、LOD、运输车辆保持可见、装载机间距、昼夜色彩 / 光强关系、近景 LOD、自动施工的完工转场与重新开始。

原来的通用 `FPS > 40` 改为“帧数推进且 FPS 为正”，并把 FPS 和完整基线样本附加为 `sandbox-baseline-metrics` JSON。轻量画质有合法的 30 FPS 目标；单台机器、未明确画质或预热时长的测量不适合作为普适 40 FPS 门槛。此变更不是性能通过结论。若要做性能门禁，应另定设备、浏览器、分辨率、画质、预热、采样时长与帧时间分位数。

嵌入窗口的完整沙盘控制用例仍仅在 desktop 项目执行。单文件施工循环用例仍在两个项目执行；这并不能代替真实手机的设置弹窗、触摸或离线 UI 检查。

## 外部服务的测试边界

默认原版游戏测试通过 Playwright 路由在内存中返回简单 HTML。它检验本站是否尊重显式载入、是否链接正确来源、是否在离开原版页后卸载 iframe，不检验第三方 Unity 的下载、引擎初始化或操作结果，也不联系 Unity 源站。

独立用例 `live original Unity game exposes its canvas and keyboard controls` 保留原来的 `Move:` 文本、canvas 可见和键盘输入冒烟检查，只有 `LEO_E2E_LIVE_ORIGINAL=1` 时才运行。它会访问外部站点，可能受网络、服务状态、嵌入政策和 WebGL 环境影响。即使 canvas 可见和按键发送成功，也不能据此声称完整通关。

播放器用例保留榜单信息 / 来源 / 曲目切换，用本地 MP3 检验播放链路。它不声称 iTunes 全部试听链接已经联网验证。

## 配置与执行注意事项

- `playwright.config.ts` 仍使用 `http://127.0.0.1:4176` 和单 worker。
- desktop 项目为 1440 × 900 的 Chromium；mobile 使用 iPhone 13 参数但明确指定 **Chromium**，不是 Safari / WebKit 实机测试。
- `npm run test:e2e` 会先构建再启动预览；直接调用 Playwright 可能测试旧的或缺失的 `dist`。
- 通用 `npm run typecheck` 的两个配置只包含应用和 Vite 配置，原本不会检查 E2E。新增静态配置专门补足这点。
- 本轮没有实际 E2E 执行结果。保留的窗口几何、图片 alpha 阈值、下载事件、真实音频解码、WebGL 帧进度、焦点和触摸断言，仍需由获准的浏览器执行验证。如失败，应先区分测试入口变化与实际功能 / 资产回退，不能删断言来制造通过。
